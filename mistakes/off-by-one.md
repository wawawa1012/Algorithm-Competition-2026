# 边界条件：off-by-one

**出现：** 2026-09-25 `remove_duplicates`（改了两轮才过）

## 症状

样例 `1 1 2 3 3 3` 通过，但"最后一个元素是全新值"时被丢弃：
`1 2 3` 输出 `1 2`，`1 1 2` 输出 `1`。

## 原因

`while (fast < size - 1)`：最后一个元素的下标是 `size - 1`，被条件排除在扫描范围外。

相关错误：`else` 分支里写成 `slow++; fast++; nums[slow]=nums[fast];`——先移动读指针再读，抄到的是下一格的值；`fast` 在末尾时会越界读（UB，输出垃圾或崩溃）。

## 防御习惯

1. 自动自测三类数据：n=1、全部相同、完全没有重复
2. 写下标条件前，先写出"合法下标范围 [0, size-1]"，再检查条件是否覆盖两端
3. 双指针节奏：先读、再写、后移动指针
4. 样例通过 ≠ AC

## 2026-10-18：Water Heater 的数组边界

- vector 大小为 n 时，最后一项是 [n-1]，读取 people[n] 已经越界。开启 -D_GLIBCXX_ASSERTIONS 后，官方样例和 n=1 都会触发断言。
- && 从左向右求值，必须先判断 b<n，再读取 beginTime[b]；所有开始事件耗尽后 b==n，先读取再检查无法保护访问。结束事件指针同样先判界。
- 写循环前明确“指针允许等于 n 作为已处理完的状态，但此时不能再解引用”。

## 2026-10-18：闭区间更新的撤销位置

- 对 [l,r] 整段加 x 时，右端 r 本身也要生效，增量从 r+1 才撤销。在 r 撤销会漏右端，l==r 时同一点一加一减会完全抵消。
- 使用一位下标事件、内部转为零位下标时，r+1 的事件可能写到 diff[n]；差分数组额外保留一格，恢复结果仍只遍历原数组的 n 项。
