# 一次统计，多次查询

## 2026-10-12：出现次数查询

学员独立想到哈希计数，但原稿把建表放在每次查询内，并返回 nums[x]。

- 时间复杂度：每次查询遍历 n 个元素，q 次查询变成 O(nq)。数据不变时，统计只应做一次。
- 算法思想 / 边界条件：x 是要查询的数值，不是数组下标。nums[x] 是取第 x 个位置，可能越界；需要查询统计表中 x 对应的次数。
- STL 使用：哈希计数表中，键表示数值，值表示出现次数。例如数组 [2,7,2,-1,7,2] 中，键 2 对应次数 3，键 7 对应次数 2。

结构：读入数据 -> 建表一次 -> 循环读取查询，每次只查表。

建表使用 mp[value] 累加是正确的；查询不存在的键时，operator[] 会插入默认值 0，这一行为本身不等于逻辑错误。需要只读查询时可使用 find，或先检查键是否存在。

复杂度要区分：unordered_map 的常规计数方案平均 O(n+q)，不保证同样的最坏上界；排序+二分或有序 map 可给出 O((n+q) log n) 的上界。

改进方向：下一次轻量练习重点检查“表里存什么”和“哪些操作只做一次”，不因选哈希而判算法方向错误。
